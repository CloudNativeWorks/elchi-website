## Platform

web

## Users

Primary: hands-on platform, SRE and DevOps engineers who run (or are about to run) fleets of Envoy proxies on VMs and Kubernetes. They arrive evaluating whether Elchi can replace hand-written xDS config or a heavier service mesh, read architecture and docs closely, and judge the product by technical precision. Confirmed with the user (2026-11-08).

The license buyer (infrastructure or security management) is reached through these engineers; the site does not target them first.

## Product Purpose

elchi.io is the marketing and documentation site for Elchi, a visual control plane for Envoy. The site explains the platform and its add-on products, shows the real product, and links to the docs (`docs-site/`, Docusaurus) and the video tutorials.

Success: a convinced engineer gets in touch for a demo or an enterprise license (contact page, info@profelis.com.tr). Confirmed with the user. Installing the free tier and reading the docs are supporting paths, not the main goal.

## Positioning

Elchi manages a whole Envoy fleet from one place without hand-written xDS: typed editors generated from each Envoy version's protobufs, two-step validation, draft/save/publish with an audit log, several Envoy versions side by side with listener upgrades that drop no requests, and security (Shield, an ext_proc sidecar in the request path) plus traffic-derived API discovery built into the same control plane.

## Operating Context

- Bilingual site: English (default) and Turkish (`/tr/`), strings in `i18n.js` and per-page string tables.
- Pages: home, features, architecture, products (Core, API Security, API Discovery, GSLB), plans and licensing, screens, videos, contact, docs.
- Stack: React 18 + Vite multi-page build with a prerender step (`npm run build` = `vite build && node scripts/prerender.mjs`); `motion`, three.js / React Three Fiber for the home hero.
- Videos come from the CloudNativeWorks YouTube channel; `videos-data.js` is generated by ai-video-factory (`pnpm video:website`), hand-written entries live in `film-data.js`.
- Screenshots are captured from a live demo environment, light and dark variants (`public/shots/`).

## Capabilities and Constraints

- Product family: Elchi Core (base platform, included in every deployment) plus licensed add-ons API Security (Shield, with built-in WAF), API Discovery and GSLB. Each add-on requires Core.
- Licensing scales with the number of managed clients (edge nodes); per-product enforcement is still being rolled out (current releases enforce the client count). Without a license the free tier runs one managed client.
- Architecture: three processes (Registry, Controller, Control-Plane) plus a lightweight edge agent on every edge host.
- Source is Apache-2.0 licensed; repositories under github.com/CloudNativeWorks. Built by CloudNativeWorks, powered by Profelis (footer).
- Performance matters: the home hero is a live WebGL scene with a poster image first; heavy media must not block the first load.

## Brand Commitments

- Voice: plain, technical and factual; claims are backed by what the product does.

## Product Principles

1. Show the real product: live screenshots, the running 3D scene and the films carry the argument, not abstract claims.
2. Write for the engineer who will check: precise terms (xDS, ext_proc, EDS), no vague superlatives.
3. Every claim must be true of the shipped product; no fabricated proof.
4. Lead the convinced visitor to a conversation (demo, license), with docs and free tier as the way to verify.
5. Both languages are first-class.
